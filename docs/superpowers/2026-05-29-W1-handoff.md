## 3. Locked decisions (summary — governance.md is authoritative)

- **Two domains.** Hedge `counterparties` = `{broker, bank_br}`, risk_manager-owned, **sanctions-screened only** (no LEI/credit dossier). New **`commercial_partners`** table, `kind ∈ {customer, supplier}`, trader-owned, **full commercial KYC** (sanctions + LEI + credit). `orders.counterparty_id` → `commercial_partners`.
- **RFQ admission gate** re-targeted `kyc_status` → effective `sanctions_status == clear` (a successful `clear` screening **OR** a risk_manager adjudication of a `flagged`). Events renamed `rfq_*_rejected_sanctions_not_cleared`. The 6 `assert_kyc_approved` call sites in `backend/app/services/rfq_service.py` (~580, 853, 1029, 1297, 1469, 1583) become `assert_sanctions_clear` — **in W3**, not W1.
- **Commercial order gate** (new): order creation refuses unless `kyc_status==approved` AND `sanctions_status != blocked` AND kind coherence (PO→supplier, SO→customer); HTTP 422 + dual-session HMAC audit (`order_rejected_kind_mismatch` / `_kyc_not_approved` / `_sanctions_blocked`, **event-specific payloads**). **This gate is W3**, not W1.
- **Sanctions** = hosted OpenSanctions (`POST /match/sanctions?algorithm=logic-v2`, `EntityMatchQuery` `queries` envelope, array-valued props). Decoupled: screening writes stored status; gates read it. `SanctionsStatus` gains an explicit **`unscreened`** member (default, NOT `clear`). Result mapping: below review → `clear`; review..hard → `flagged`; ≥hard → `blocked`. Error row written on a **separate committed session** (commit-before-raise) with `result=NULL`; never silently `clear`. **Adjudication**: risk_manager overrides a `flagged` ONLY (not `blocked`) via `POST {id}/adjudicate-sanctions`, immutable `sanctions_adjudications` row, valid only against the latest still-`flagged` screening.
- **LEI** = GLEIF `api.gleif.org/api/v1/lei-records/{lei}` + offline ISO 7064 checksum; **warn-not-block**.
- **Credit/terms** = asymmetric by kind (customer: limit + payment conditions; supplier: approved value + terms), **`Decimal`**, risk_manager-approved; utilization gate **deferred**.
- **Identity-edit reset**: editing a screening-relevant identity field (`name`/`country`/`tax_id`/`lei`) on a partner (commercial OR hedge) carrying any non-`unscreened` evidence resets it fail-closed (re-screen + re-approve).
- Generic PATCH **excludes** `kyc_status` + credit/terms for ALL actors (incl. risk_manager) — those change only via dedicated audited endpoints.

## 6. Institutional constraints / gotchas (from CLAUDE.md + this effort)

- **Constitution is supreme.** `docs/systemconstitucion.md` + `docs/governance.md` override convenience. No silent fallback, no heuristic correction, no mixed regimes, no mutation without HMAC audit evidence. Backend is authoritative for economics.
- **Precision:** money = `Decimal` end-to-end; float parsing prohibited on ingest.
- **Audit survives rollback:** routes run inside `unit_of_work` which rolls back on ANY exception. The order gate + screening-error evidence use the **dual-session pattern** (`backend/app/services/kyc_gate.py`) — write audit on a separate committed `SessionLocal`, then raise.
- **Migrations:** SQLite in tests, Postgres in prod. The `alembic-fresh-postgres` CI job catches ENUM-lifecycle issues SQLite misses. Single-head chain enforced.
- **Tests:** `cd backend && python -m pytest -x -q`; lint `ruff check .`. Frontend: `cd frontend-svelte && npm run check && npm run test`.
- **Pre-push hook:** `.githooks/pre-push` runs an LLM dispatch-review and needs `ANTHROPIC_API_KEY` (absent in this env). It fired on W0's non-dispatch docs and blocked the push; Andrei authorized `git push --no-verify` for those. For real code pushes, prefer having the key set; only `--no-verify` with explicit authorization.
- **Review gate = Codex Connector** (sole gate as of 2026-05-26). `+1` reaction on the PR = acceptance; `eyes` = processing (NOT acceptance). Query `/issues/{N}/reactions`.
  - ⚠️ **Codex inline comments LAG the review object.** A COMMENTED review can show 0 comments on an immediate poll and then sprout findings ~1–2 min later. **Never declare a review "clean" from an immediate empty poll** — wait ≥60–120s, re-poll, and check **sibling review ids** (Codex sometimes posts two reviews per run). This caused a near-miss on W0 (a 4-finding review mis-read as clean).
- **Don't duplicate governance prose** in spec/plan/dispatch docs — it drifts and generates recurring "parallel-site" review findings. Reference governance by **section name**. (W0's plan had to be gutted to pointers for exactly this reason.)
- **Workflow:** this effort follows brainstorm → spec → writing-plans → executing-plans, and the repo's amendment → dispatch → implementation protocol. Each wave = its own spec/dispatch + PR.
